# Расход токенов ИИ-гида и переход на DeepSeek V4 Flash

Дата замера: 10.08.2026. Каталог: `museum-ai-guide` (`b1glrl280tkmpcnt3p1l`).
Инструмент: `scripts/llm_token_probe.py` — промпты импортируются из
`app/services/llm.py`, поэтому замер не расходится с продом при правке промптов.

## 1. Системные промпты и лимиты выхода

Гид делает **четыре разных типа вызова**, у каждого свой system-промпт и свой
лимит. Общая точка входа — `llm._llm_complete`.

| Сценарий | Код | `max_tokens` | `temperature` |
|---|---|---:|---:|
| Рассказ (`POST /guide/story`) | `llm._llm_story` | 1500 ¹ | 0.6 |
| Вопросы-подсказки | `llm._llm_questions` | 200 | 0.7 |
| Диалог (`POST /guide/chat`) | `llm._llm_chat` | 800 | 0.6 |
| Числа прописью для TTS | `llm.to_spoken_text` | 2000 | 0.0 |

¹ было 800, поднято до `LLM_MAX_TOKENS_STORY=1500` — см. §4.

### Рассказ
```
Ты — ИИ-гид музея Фаберже.
```

### Вопросы-подсказки
```
Ты помогаешь придумать вопросы для диалога с гидом.
```

### Диалог — `_CHAT_SYSTEM`
```
Ты — ИИ-гид музея Фаберже в Санкт-Петербурге (Шуваловский дворец). Отвечай
кратко и по делу, на русском языке.
Ниже может быть приложена справка о зале или экспонате, рядом с которым сейчас
находится посетитель. Это ПОДСКАЗКА, а не граница твоих знаний: используй её,
если она относится к вопросу, и просто игнорируй, если вопрос об этом не спрашивает.
Если ответа в справке нет, отвечай по своим знаниям о музее, коллекции Фаберже,
ювелирном искусстве и истории России. НЕ отвечай «в предоставленных материалах
нет информации» и не ссылайся на то, что справка чего-то не содержит, — это
выглядит как отказ. Если не знаешь ответа, так и скажи прямо.
Никогда не выдумывай то, чего не знаешь наверняка: планировку музея, этажи,
маршруты, номера залов, имена мастеров и даты. Если этих сведений нет в справке,
прямо скажи, что не знаешь, и предложи уточнить у сотрудника музея.
```

Последний абзац добавлен 10.08.2026 по итогам аблации промпта — см. §6.1.

### Числа прописью для TTS — `_SPOKEN_SYSTEM`
```
Ты — редактор текста для синтеза речи (TTS). Твоя единственная задача —
переписать русский текст так, чтобы его правильно прочитал синтезатор речи:
все римские и арабские числа заменить словами В ПРАВИЛЬНОМ падеже, роде, числе
и разряде (количественное/порядковое) по смыслу предложения.
```

## 2. Главное: DeepSeek живёт на другом эндпоинте

Прежний код ходил в `llm.api.cloud.yandex.net/foundationModels/v1`. Этот эндпоинт
знает **только семейство `yandexgpt`**:

```
POST foundationModels/v1/completion, modelUri=gpt://<folder>/deepseek-v4-flash/latest
→ 404 {"error":"unknown model 'gpt://deepseek-v4-flash/latest'"}
```

Полный каталог виден только через OpenAI-совместимый шлюз
`ai.api.cloud.yandex.net/v1`:

```bash
curl -H "Authorization: Bearer $(yc iam create-token)" \
     -H "OpenAI-Project: b1glrl280tkmpcnt3p1l" \
     https://ai.api.cloud.yandex.net/v1/models
```

Доступно в каталоге: `deepseek-v4-flash`, `aliceai-llm`, `aliceai-llm-flash`,
`gpt-oss-120b`, `gpt-oss-20b`, `qwen3-235b-a22b-fp8`, `qwen3.6-35b-a3b`,
`yandexgpt-5.1`, `yandexgpt-5-pro`, `yandexgpt-5-lite`, `speech-realtime-*`.

Из-за этого смена модели — **не только правка env**, но и смена транспорта
(формат payload, схема авторизации, разбор ответа). Сделано, см. §4.

## 3. DeepSeek V4 Flash — reasoning-модель

Размышления включены **по умолчанию**, тарифицируются как выходные токены и в
`content` не попадают. На боевых лимитах это ломает гида:

| Прогон | Выход, сумма | Пустых ответов | Обрезано | Латентность |
|---|---:|---:|---:|---:|
| DeepSeek, reasoning по умолчанию | 6191 | **2 из 10** | 4 из 10 | 12.84 с |
| DeepSeek, `reasoning_effort=none` | 1959 | 0 | 0 | 4.82 с |

Как выглядел провал: на «Как пройти в Рыцарский зал?» модель израсходовала все
800 токенов на размышления (2274 знака) и вернула `finish_reason=length` с
**пустым `content`**. Посетитель увидел бы пустой пузырь, а в аналитику ушло бы
«ответ дан».

Поэтому в коде появился `LLM_REASONING_EFFORT=none` (значение по умолчанию) и
явная защита: пустой `content` больше не отдаётся молча, а поднимает
`UpstreamError` с диагностикой.

## 4. Изменения в коде

| Файл | Что |
|---|---|
| `app/services/llm.py` | транспорт → `ai.api.cloud.yandex.net/v1/chat/completions`; payload в формате OpenAI (`messages[].content`, `max_tokens`); авторизация `Bearer` вместо `Api-Key`; каталог заголовком `OpenAI-Project`; `reasoning_effort`; защита от пустого `content`; helper `model_uri()`; `_yandexgpt_*` → `_llm_*` |
| `app/config.py` | `llm_api_base`, `llm_reasoning_effort` (по умолчанию `none`), `llm_max_tokens_story` (1500) |
| `.env.example` | документация трёх новых переменных + команда листинга моделей |
| `scripts/llm_token_probe.py` | новый шлюз, колонка reasoning, флаг пустого ответа, `--reasoning`, `--list` |

`YANDEXGPT_MODEL_URI` намеренно **не переименована** — иначе пришлось бы править
окружение уже развёрнутой функции `faberge-api`.

Лимит рассказа поднят с 800 до 1500: DeepSeek пишет в ~2.4 раза длиннее
YandexGPT и на 800 обрывался на полуслове (`…о гении человека, который смог
остановить мг`). Обрыв хуже длинноты — его ещё и озвучит TTS.

Проверено живым вызовом прод-кода: `generate_story`, `chat`, `to_spoken_text`
отрабатывают на DeepSeek, защита от пустого ответа срабатывает.

## 6. Качество: где DeepSeek выдумывает

Тексты обеих моделей на одних промптах. DeepSeek живее пишет, но уверенно
сочиняет факты, которых нет в справке.

**Навигация (#8)** — справка содержит только «Зал: Синяя гостиная».

- YandexGPT: «мне нужно знать, где вы сейчас находитесь… обратитесь к сотруднику»
- DeepSeek: «Рыцарский зал на **втором этаже**… вернитесь в анфиладу, поднимитесь
  по **парадной лестнице**… **западная часть** дворца»

Планировки в справке нет. Посетитель пойдёт по выдуманному маршруту.

**Мастер (#4)** — в справке мастер не указан вообще.

- YandexGPT: «мастер не указан в справке»
- DeepSeek: «Михаил Перхин… впрочем, он умер в 1903, значит Генрих Вигстрём»

**Число яиц (#9):** YandexGPT — 50; DeepSeek — «54 создано, 46 сохранилось».
Общепринято: 50 императорских, сохранилось ~43. Ошибаются обе, DeepSeek —
конкретнее и убедительнее.

**Markdown:** DeepSeek вставил `**жирный**` в рассказ (1 ответ из 10).
`app/services/text_normalize.py` разметку не снимает — звёздочки уйдут в TTS.

### 6.1. Аблация промпта: виноват ли запрет «не отвечай „нет информации“»

Гипотеза: запрет из `_CHAT_SYSTEM` отнимает у модели право сказать «не знаю» и
толкает её выдумывать. Проверено на двух вопросах, где ответа в справке
объективно нет (планировки музея в данных нет вообще; мастер не указан).
Три варианта промпта × 2 модели × 3 прогона:

| Модель | Вопрос | A: как было | B: без запрета | C: запрет + антивыдумка |
|---|---|---|---|---|
| YandexGPT | навигация | 0/3 выдумок, признал 1/3 | 0/3, признал **3/3** | 0/3, признал **3/3** |
| YandexGPT | мастер | 0/3, признал 2/3 | 0/3, признал 1/3 | 0/3, признал **3/3** |
| DeepSeek | навигация | **3/3 выдумок**, признал 0/3 | **3/3**, признал 1/3 | 1/3, признал 3/3 |
| DeepSeek | мастер | **3/3**, признал 0/3 | **3/3**, признал 0/3 | **3/3**, признал 1/3 |

**Гипотеза подтвердилась для YandexGPT.** С запретом на навигацию модель вместо
честного «не знаю» выдавала воду: «двигайтесь в направлении выхода, ориентируясь
на указатели». Без запрета — «уточните ваше местоположение, и я подскажу
маршрут», 3 раза из 3.

**Для DeepSeek запрет ни при чём** — без него выдумки остались 3/3. Модель
называет Перхина и Вигстрёма там, где мастера в справке нет вовсе.

Просто убрать запрет нельзя: он чинил баг 28.07, а на вопросе про мастера
вариант B оказался хуже исходного (2/3 → 1/3). Взят **вариант C** — запрет
сохранён, добавлен явный пункт против выдуманной планировки, маршрутов, имён и
дат.

**Регрессия на баг 28.07 проверена** (`yandexgpt/latest`, 3 прогона на кейс):

| Вопрос | Ожидание | Отказов вида «в материалах нет» |
|---|---|---:|
| «Расскажи про Петра I» | ответить | 0/3 |
| «Чем знаменит Фаберже?» (без справки) | ответить | 0/3 |
| «Что такое гильошированная эмаль?» | ответить | 0/3 |
| «Кто был мастером этого яйца?» | признать незнание | 0/3 ✓ признал |
| «Как пройти в Рыцарский зал?» | признать незнание | 0/3 ✓ признал |

Стало: «К сожалению, я не знаю, кто был мастером этого яйца» вместо выдуманного
имени. На навигации гид всё равно не остаётся без ответа — маршрутную плашку
`location` подставляет детерминированная ветка B7 в `guide.py` из каталога, а не
модель.

### 6.2. Остались ли галлюцинации у YandexGPT на новом промпте

11 вопросов × 2 прогона. Две группы: проверяемые факты и вопросы, данных по
которым у нас нет вообще.

**Вопросы без данных — 10/10 честных отказов, ноль выдумок:**

| Вопрос | Ответ |
|---|---|
| На каком этаже Синяя гостиная? | «не могу точно сказать… уточните у сотрудника» |
| Сколько стоит билет? | «уточните стоимость у сотрудника музея» |
| Во сколько закрывается музей? | «обратитесь к сотруднику музея» |
| Сколько экспонатов в Синей гостиной? | «не знаю точного количества» |
| В какой витрине лежит это яйцо? | «уточните у сотрудника музея» |

Это ровно тот класс выдумок, на который жаловался заказчик, — он закрыт.

**Проверяемые факты — 5 из 6 верны, 1 ошибка:**

| Вопрос | Ответ модели | Проверка |
|---|---|---|
| Сколько императорских яиц? | 50 | верно |
| Первое яйцо, год и название? | 1885, «Курочка» | верно |
| **Кто основал фирму Фаберже?** | **«Пётр Карл Фаберже»** | **неверно: фирму основал Густав Фаберже в 1842, Карл возглавил её в 1872** |
| В каком здании музей? | Шуваловский дворец | верно |
| Что такое гильошированная эмаль? | гравировка + эмаль поверх | верно |
| Кому Николай II дарил яйца? | Александре Фёдоровне и Марии Фёдоровне | верно (формулировка «и высокопоставленным лицам» размыта: императорские яйца шли только этим двум) |

**Вывод.** Промпт закрыл выдумки про музей — планировку, маршруты, витрины, цены,
имена мастеров. Осталась общая фактология по истории Фаберже, и промптом она не
чинится: этих сведений нет ни в справке, ни в каталоге, модель отвечает из
собственных знаний. Если точность здесь важна, лечится наполнением
`exhibits.raw_history` и справочника, а не настройкой модели.

## 7. Проекция на трафик

Один визит: 1 рассказ + 3 реплики диалога + 1 озвучка. Важно: `llm.chat`
дозапрашивает вопросы-подсказки **на каждой реплике** — один ход посетителя это
**два** запроса к модели.

| | Запросов | YandexGPT вх/вых | DeepSeek вх/вых |
|---|---:|---:|---:|
| Рассказ + подсказки | 2 | 392 / 322 | 499 / 944 |
| 3 реплики (chat + подсказки) | 6 | 1710 / 282 | 2244 / 729 |
| Озвучка | 1 | 328 / 86 | 431 / 130 |
| **На визит** | **9** | **2430 / 690** | **3174 / 1803** |

На 1000 визитов: YandexGPT ≈2.43 млн вход / 0.69 млн выход;
DeepSeek ≈3.17 млн вход / 1.80 млн выход.

Отдельная статья — вопросы-подсказки: 200–256 входных токенов на КАЖДУЮ реплику,
около 40 % всего входа. `max_questions=0` в запросе убирает вызов целиком.

## 8. Рекомендация

Технически переход готов: код переведён на новый шлюз, reasoning выключен,
обрывы устранены, прод-код проверен живыми вызовами. Осталась одна строка:

```
YANDEXGPT_MODEL_URI=gpt://b1glrl280tkmpcnt3p1l/deepseek-v4-flash/latest
```

Но по замерам DeepSeek V4 Flash **дороже и медленнее** текущей модели (+60 %
токенов, ×3 латентность) и при этом склонен выдумывать планировку музея и имена
мастеров. Для гида, который ведёт посетителя по залам, выдуманный маршрут — это
жалоба, а не стилистическая мелочь.

Перед переключением стоит решить, что именно не устраивает в YandexGPT. Если
скорость — DeepSeek её ухудшает. Если живость языка — она достигается правкой
промпта дешевле. Если всё же переходим, до продакшена нужно:

1. ужесточить `_CHAT_SYSTEM` запретом выдумывать планировку и имена мастеров;
2. снимать markdown перед TTS (`text_normalize.py`);
3. прогнать нагрузочный сценарий — 17 с на рассказ против 4.9 с меняет профиль.
